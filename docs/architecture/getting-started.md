# 入门与任务阅读路线

本页提供阅读顺序。项目进度见[阶段跟踪](../../Prima%20OS%20实现阶段.md)，架构术语见[术语表](glossary.md)。

## 首次阅读

1. 读[文档中心](../README.md)的权威分工，明确设计、实现、测试与签署分别由谁说明。
2. 读[系统地图](system-map.md)，定位 POSIR、COSIR、HexArc、运行时、服务和 LibOS。
3. 读[白皮书](../../Prima%20OS.md)的摘要、§3 研究假设、§4 分层、§14 可证伪标准与§19 非目标。
4. 读[原语规范](../../COSIR%20原语规范.md)的§1–6、§16 全局不变量与§18 细化要求；再按任务深入具体原语。
5. 读[当前阶段](../../Prima%20OS%20实现阶段.md)，跟到当前出口评审及其限制。

## 按角色选择最小充分上下文

| 工作 | 必读材料 | 可以后读 |
|---|---|---|
| 内核机制 | 主题原语 + 对应 W 不变量 + kernel/prima-ostd 边界 + 最新整改 | 不相关的 libc 历史计划 |
| 原生运行时/服务 | 运行时主题 + ABI/协议定义 + stage4 收口与复核 | POSIX 的未采纳候选规格 |
| C/musl 适配 | 兼容主题 + profile + compat 台账 + C 探针与补丁 | 无关的硬件候选架构 |
| 模型/证明 | 形式化主题 + lean/README 映照契约 + 明确的证明边界 | QEMU 成功不能替代缺失证明 |
| 项目评审 | 阶段退出条件 + 签署报告 + 后续整改 + 活跃问题 | 单独一份完成计划不够 |
| 文档贡献 | 治理规范 + 模板 + docs.py check | 不需要启动 QEMU 才能写导航 |

## 开始修改之前

用[主题地图](topics/README.md)找到契约、设计、计划与报告；读它们的适用范围和后继关系，再读实现。报告中记录的失败、容量负例和 workaround 属于上下文的一部分。

确认三件事：要改的语义由哪份文档定义；行为落在哪个 crate/用户态服务；用什么证据能观测这次改变。记录无法解决的歧义，不靠“更新日期较新”裁决语义。

## 一次完整交付

行为变更依次更新契约、实现、相关验证、报告、阶段跟踪和主题路由；纯导航变更记录链接与目录检查。命令和证据范围见[开发手册](development.md)，报告字段见[维护手册](documentation-maintenance.md)。

架构解释从[系统与代码地图](system-map.md)和主题包进入；旧对话摘要已移除，原因与恢复版本见[生命周期台账](../lifecycle.json)。遇到冲突返回白皮书、原语规范和阶段跟踪。
