# S6-M2：大映像帧向量与有界资源预算

## 范围与上位关系

本切片接续[按需 ELF 输入](2026-10-31-stage6-streamed-elf-input.md)，推进
[阶段 6–7 计划](../plans/2026-10-27-stage6-7-refinement.md)的 S6-M2 装载资源。
遵守 [COSIR §5.1/§7.5/W6](../../../COSIR%20原语规范.md)：帧向量保留真实逐帧顺序，
不得用物理连续区间代替；销毁只归还该 Segment 的实际归属帧。
本契约不发布新的 syscall、Linux profile 或白名单成员，证据见[容量报告](../reports/2026-10-31-stage6-exec-frame-capacity.md)。

## 资源边界

| 资源 | 本切片预算与限制 |
|---|---|
| 普通 `memseg_create` / 平台段 | 每段仍≤149 页 |
| boot 服务映像 | 仍≤192 页，与 exec 存储区间分离 |
| 私有 exec Segment | 每次≤640 页，包含新栈；当前 8 页栈下可承载≤632 页 PT_LOAD |
| Segment 对象及归属标签 | 全局64；私有 exec 标记仍为 u64，编译期拒绝超过64的配置 |
| CPU 数据帧归属 | 全局2048；普通段、文件源、旧映像、新映像与后续 COW 共用，不是每任务保证 |
| 页表帧 | 全局256，保持原上限 |
| 逻辑用户映射 | 全局2048条；延迟回收队列按既有 `1+3*映射额度` 关联计算 |
| 分配器归还栈 | 2048+256=2304；所有可归还的活动数据/页表帧均须有位置 |
| kernel image 帧 | 仍≤2048，逐帧登记，不变成区间判定 |

冻结 busybox 需要526个载入页，连同当前栈为534页。文件源526页（保守预算）、旧/新各534页、
基础预算320页及 retained/COW 余量96页合计2010，落在全局2048额度内。
这是容量配置的推导，不是所有服务/并发组合均可准入的保证；其它活动分配仍可能占满额度。

## 表示、准入与回收

- 保持内联 `SegmentFrames::Vector` 的149项容量。大 exec 复用外部 arena，记录实例、
  起点与长度；boot 保留前192槽，其后2048槽供 exec 元数据使用，不分配相应数量的物理帧。
  每项保存真实 FrameId，包括物理帧0；数据帧实际分配仍走唯一归属注册表。
- 外部 run 在持有独占 BootstrapState 的非调度区间内选择和填充，使用有界 first-fit。
  已填前缀在分配/铸造失败后归还并清空；成功对象销毁时先归还帧，再清空自己的元数据。
  活动 run 不重叠；普通调用不能借此取得大段根能力。池的碎片可能导致准入失败，
  v1 不承诺在总空闲槽足够但不连续时仍成功。
- kernel image 的物化向量移入独立静态存储，复用该注册表的 owner-region 身份；
  每实例内容隔离。不增加 BootstrapState 字段，也不扩大 SegmentFrames 按值尺寸。
  注册表副本与既有 owner arena 一样引用同一实例存储，不能当成深拷贝快照。
- 全局帧归属表是无序集合；每个 Segment 的顺序由独立向量保持。单帧删除可用末项补位，
  整段回收一次扫描归属表，避免每归还一页都移动整张表。回收栈的验证仍必须先于归属删除。
- 地址空间替换仍先构造私有根、完成输入与资源验证，再提交；失败保持旧映像可执行。
  已建立暂存 Segment 的回收沿用上一切片的退栈边界。额度扩大不取消错误、审计或栈 guard。

## 验证与非目标

host 验证实例隔离、真实向量顺序与零帧、run 复用/耗尽、普通段边界、交错归属回收、
2048数据帧及256页表帧全部归还并再次分配。保留13 KiB BootstrapState、32 KiB
FrameRegistry 的大小守卫及32 KiB syscall 栈 guard。

W7 用526页完整合成文件验证全部页的不同 marker，原生分支另验证部分分配失败、
640页额度、四次失败回滚，以及大映像再次从自身只读映射 exec；Linux 同源只对照
合成文件的526页内容检查，不把原生额度/再次 exec 分支冒充 Linux 差分。

本切片不提供大文件 VFS 来源，不执行冻结 busybox，不验证其 libc/TLS/栈或 LibOS。
Gate 的能力/陷阱/rax 答复及 G1–G3 仍是独立工作，不因本契约完成而勾选阶段条件。
扩大段表超过64、共享 root、SMP、改变 first-fit 或使用浅副本进行事务快照时须重审。
