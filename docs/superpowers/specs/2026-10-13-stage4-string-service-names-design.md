# SPEC-101 设计：字符串服务名与端点名的运行期指派（闭合 SPEC-095 §5.1）

> 状态：探索实现；不构成 S4-D2 验收或稳定 ABI
>
> 前置：[SPEC-095 运行期服务注册表](2026-10-12-stage4-runtime-service-registry-design.md)

## 1. 本片要回答的问题

SPEC-095 §5.1 登记两项未决：

1. **名字仍是 64 位码**（`1`/`2`），非字符串路径；
2. **注册仍是编译进二进制**（端点不能运行期改名）——`SERVICE_SELF_NAME` 是端点源码里的常量。

本片把两项都做掉：服务名改为 **ASCII 字符串令牌**；端点的注册名由**服务管理器在
`task_create` 时运行期指派**（经请求块新字段 → 新任务初始帧 `rcx`），端点二进制不含任何
服务名字面量。

## 2. 机制

### 2.1 字符串服务名

服务名 = 最多 5 字节的 ASCII 令牌，按 little-endian 打包进一个 `u64` 的低 40 位（尾部补 `0`）：

- `"alpha"` → `0x0061_6870_6c61`
- `"beta"` → `0x6174_6562`
- 未注册负例 `"ghost"` → `0x7473_6f68_67`

打包函数在内核（`user::service_name`）与运行时（`protocol::pack_service_name`）各一份，语义同款。
5 字节上限由自报 payload 的位宽决定（见 §2.3）。

### 2.2 端点名的运行期指派

`task_create` 请求块（原 10 qword）新增第 11 个 qword `name`（`[rdx+0x50]`）：

- 内核 `TaskCreateRequest` 增细化层字段 `name`；`register_created_task` 把它按值写入新任务初始帧
  **`rcx`**（第 4 个入口参数；SysV 第 4 参寄存器）。
- 服务管理器（`init`）在创建两个端点时把 `SERVICE_NAME_ALPHA` / `SERVICE_NAME_BETA` 写入请求块；
  端点 `_start` 第 4 参数（`rcx`）即其注册名，端点在自报消息里回报该值。

判决性：`prima-smoke`（`ALPHA` 端点 + 客户端双角色）二进制里唯一的名字字面量是**客户端请求名**
`"beta"`；而 `ALPHA` 端点回报的注册名是 `"alpha"`（与 `"beta"` 相异），故它**只可能**来自运行期
指派的 `rcx`。`prima-beta`（纯 `BETA` 端点）二进制里**没有任何**服务名字面量，其注册名
`"beta"` 同样只能来自 `rcx`。

### 2.3 自报 payload 布局

端点自报消息 payload 由 SPEC-095 的 `tag(48..63) | name(16..31) | id(0..15)` 改为：

```
tag(48..63) | name(8..47) | id(0..7)
```

- `tag` = `SERVICE_ID_TAG` 高 16 位（不变）；
- `name` = 40 位服务名（§2.1）；
- `id` = 自身 task id 低 8 位（task id ≤ 12，足够）。

`init` 收集自报时：`id = payload & 0xff`；`name = (payload >> 8)` 再 `shl/shr 24` 掩出低 40 位
（不用掩码寄存器，避免占用 `rcx` = Y 页基址）。

### 2.4 客户端请求名保持众所周知的常量

客户端是**请求方**，用固定名寻址是常态，故 `prima-smoke` 客户端角色仍写入众所周知的
`SERVICE_NAME_BETA`（`prima-runtime::protocol` 的共享常量）。运行期指派的是**端点**的注册名。
（历史任务 3 亦走此路径，其请求名不被任何见证读取。）

## 3. 判决性见证（`service_selected_ready`，seq 28）

```
name=0x61746562;...;reg_a_name=0x6168706c61;reg_b_name=0x61746562
```

- `reg_a_name=0x6168706c61`（`"alpha"`）、`reg_b_name=0x61746562`（`"beta"`）：两个端点回报的
  注册名是**服务管理器运行期指派**的 ASCII 令牌，非编译期常量（见 §2.2 的判决性推理）。
- `name=0x61746562`（`"beta"`）：客户端从共享段写下的请求名，仍是众所周知常量；经按名扫描命中
  注册表 B 项 → `resolved=0x2`。
- `unknown=0x0`：未注册名 `"ghost"` 扫描未命中 → `NONE`（拒绝转发）。

## 5. 未决与登记

1. 服务名上限 **5 字节**（自报 payload 的位宽约束）；更长名字需把名字移入共享段或改用多条消息。
2. 注册表仍是 `init` 内 Y 页 **2 项**表 + 线性扫描；未引入内核侧注册对象，也未支持 N 项动态扩容。
3. 客户端的请求名仍是编译期常量（客户端寻址语义）；只有**端点注册名**是运行期数据。
4. **不勾选** S4-D2 或任何阶段 4 交付项/退出条件；闭合判断交复核者。
5. 快路径保存块与中断帧一致性、PCID/嵌套/多核仍未涉及。
