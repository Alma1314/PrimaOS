# 阶段 6–7 前置裁决（D11–D16）

承接[阶段 6–7 细化提案](../plans/2026-10-27-stage6-7-refinement.md)的 D11–D16 与
[阶段跟踪](../../../Prima%20OS%20实现阶段.md)的决策日志。这些是**组织级/作者裁决**项；
本文记录 2026-10-28 作者委派下做出的裁决内容、依据、代价与重裁触发。

## 性质与效力

- 本文是**范围裁决**，不是实现证据，也不签署任何阶段。
- 裁决只决定「做什么、按什么顺序、退出条件怎么写」，不改变阶段 0–5 已签署范围，
  不改变 [profile v2](2026-10-25-stage5-profile-v2.md) 的冻结内容。
- 每项结论都可重裁：触发条件写在各自的「重裁触发」里。裁决不是永久冻结。
- 裁决不启动阶段 6：阶段 6 的启动仍是作者单独决定（见[启动条件](#阶段-6-启动条件的直接后果)）。

## 裁决摘要

| ID | 裁决 | 一句话理由 |
|---|---|---|
| D11 | 维持 D4/SPEC-152：动态链接留阶段 7 | 已有裁决与签署，本次不重开 |
| D12 | 白名单 = Ubuntu `busybox-static 1.36.1` 的 6 个 applet + 2 个自写探针，`sha256` 固定 | 可复核的"通过"定义必须钉死制品，否则 S6-X1 无法关闭 |
| D13 | `AT_RANDOM` 作为确定性非机密兼容字段提供（16 字节公开常量） | 未修改二进制是 SSP 构建，缺该字段会把兼容问题伪装成安全选择 |
| D14 | 7-A（多 LibOS 并存）升为阶段 7 最高优先级，并在阶段 6 动工前做有界探索原型 | 唯一无法被"内核直接实现 Linux ABI"复制的差异点，且单核即可证伪 |
| D15 | SMP 之前先做"状态按 CPU 分区"重构，禁止在单一全局状态上直接加锁 | 先加锁会先死在性能上，返工成本最大 |
| D16 | 阶段 7 采纳 7-0/7-A…7-H 子轨拆分，各自带退出条件 | 笼统"扩展与硬化"无法签署，也无法排序 |

## D11：`ld.so` / 动态链接归属

**裁决：维持——动态链接属阶段 7（7-E），阶段 6 的输入必须无 `PT_INTERP`。**

依据：D4 与 [SPEC-152](../reports/2026-10-27-stage5-exit-signoff.md) 已裁定阶段 5 静态链接、
动态链接留阶段 7 候选；DOC-002 的"ld.so 随阶段 5 交付"P0 与之冲突，以签署为准。本次
唯一的动作是把它作为**前裁决**记录，避免阶段 6 启动时再被重新打开。

- 落地：装载器遇到 `PT_INTERP` 继续返回 `Dynamic`（`ENOEXEC`），不做静默忽略。
- 重裁触发：只有在白名单出现必须动态链接的成员时才重开；届时须先改白皮书阶段定义。

## D12：阶段 6 白名单成员与版本

**裁决：冻结为下表制品与成员；成员、版本、`sha256` 任一变化都算新裁决。**

制品（唯一候选，本次实测）：

| 项 | 值 |
|---|---|
| 包 | Ubuntu noble `busybox-static` `1:1.36.1-6ubuntu3.1` |
| 路径与大小 | `/usr/bin/busybox`，2 124 608 B |
| `sha256` | `dbac288c29ba568459550a2da9e7ae0ded6b1fc728ee9fad3044c44e62d6ac14` |
| 实测属性 | `ET_EXEC`、无 `PT_INTERP`、4 个 `PT_LOAD`（第 4 段 `vaddr=0x5fc820`/`offset=0x1fb820` 同余而非页对齐）、`PT_TLS`、`GNU_RELRO`、`GNU_STACK=RW`、SSP 开启（2 402 处 `%fs:0x28`） |

成员（6 个 applet + 2 个自写探针），按"覆盖的 syscall 簇"选取，不按知名度：

| 成员 | 覆盖簇 | 为什么选它 |
|---|---|---|
| `true` | `exit_group` | 最小启动/退出路径 |
| `echo` | `write` | 最简写路径，输出可逐字节比对 |
| `cat` | `openat`/`read`/`close`/`write` | 文件读链路 |
| `ls` | `getdents64`/`newfstatat`/`ioctl(TIOCGWINSZ)` | 目录遍历与元数据 |
| `uname` | `uname` | 无副作用的信息类 syscall |
| `sort` | `read`/`write`/`brk`/`mmap` | 内存分配与批量 I/O，stdin→stdout 确定性输出 |
| 探针 P1（自写） | 裸 `syscall` 指令 + errno/EINTR 语义 | 明确"递送"而不是"重定向 libc" |
| 探针 P2（自写） | TLS（`arch_prctl`）/futex 式等待 | 线程环境的最小可用性 |

冻结规则：

1. `S6-X1` 只对上述冻结集成立；**不得**用"换一个能跑起来的二进制"来关闭它。
2. 同一制品同时用于 Linux 参考侧差分（复用 `xtask/src/linux.rs` 的 pinned guest），
   保证"同源"不是靠重新编译另一个版本凑出来的。
3. 白名单清单以 `sha256` + 上述 ELF 属性入库（`docs/superpowers/compat/` 下的台账或专门
   manifest），缺失或哈希不符即视为白名单未定义。
4. `busybox` 的 applet 选择不涉及写盘、网络、账号与终端交互；需要这些的成员再开新裁决。

重裁触发：某成员被证明要求超出 LibOS v1 的 syscall 簇且不可裁剪时，可替换成员，
但必须在阶段跟踪决策日志留痕并重算 S6-M3 的范围。

## D13：无熵条件下的 `AT_RANDOM` / canary 策略

**裁决：提供 `AT_RANDOM`——内容是 16 字节**公开、确定**常量，明确不宣称机密性或缓解作用。**

依据（本次实测，不是推测）：冻结制品是 SSP 构建（2 402 处 `%fs:0x28`）。canary 由 libc
启动期写入 TLS 槽再逐函数比对，其初值来自 `AT_RANDOM` 或后端回退。因此

- **缺 `AT_RANDOM` 会把"兼容性缺口"伪装成"安全选择"**：要不要提供它是"未修改二进制能否
  启动"的问题，不是"我们是否安全"的问题；
- 项目当前没有可信熵源，提供"看起来随机"的值只会制造不可审计的主张。

具体决定：

1. `build_initial_stack` 在栈上写入 16 字节常量 `PRIMA-RND-16BYTE`，`AT_RANDOM` 指向它；
   该地址必须与其它 `auxv` 指针一样落在可读栈页内。
2. 书面弱化声明（写入 profile v1 与阶段 6 签署报告）：本系统**无 ASLR、无可信 canary、
   无密钥；任何"抗利用"论证不得引用 `AT_RANDOM`**。canary 只提供"栈溢出检测"这一
   完整性作用，且其值可预测。
3. Prima 自建目标维持既有 SSP-off（不改 SPEC-152 冻结内容）；本裁决只覆盖**第三方
   未修改二进制**的启动需求。
4. 不加 `AT_PLATFORM`、`AT_SYSINFO_EHDR`（无 vDSO）；`AT_HWCAP=0` 保持"不宣告可选特性"。

重裁触发：出现可信熵源（硬件随机、可信时间混合 + 政策）时重开；任何安全主张必须以
新裁决为前提，不能从本裁决推出。

## D14：多 LibOS 并存的位置与顺序

**裁决：7-A（多 personality 并存）为阶段 7 最高优先级（P0，研究核心），并在阶段 6 动工前
完成一次有界探索原型。**

依据：白皮书阶段 7 的候选列表（SMP、驱动、动态链接、计量、撤销、恢复、第二架构）里
**没有**项目的核心研究假设；而 7-A 是唯一无法被"内核直接实现 Linux ABI"路线复制的差异点
（对照 [framekernel 差距分析](../reports/2026-08-16-framekernel-gap-analysis.md) 的 H4 反方基线），
且单核即可验证。越晚做，per-LibOS 根视图、服务发现与崩溃恢复的架构债越大。

探索原型（≤ 2 人周，单核，不新增内核机制）：

- 用现有 POSIX 子集与 capability 机制造两个独立根视图；
- 一个共享 log 服务，经能力授权访问；
- 跨域请求被拒（`EACCES`）且审计可重建；
- 单侧崩溃不影响另一侧。

原型性质与停止条件：**探索证据，不勾选阶段 6/7 任何条件**。若两个独立根视图 + 跨域拒绝
做不出来，说明架构假设有问题——此时暂停阶段 6 并回到架构假设评审，而不是继续投入
18–29 人周。完整 7-A 交付仍在阶段 6 之后（它依赖阶段 6 建立的 LibOS 语义）。

这一安排与[阶段晋级规则](../../../Prima%20OS%20实现阶段.md)第 2 条一致：前一阶段未满足退出
条件时，后一阶段可以做探索原型，但不能因此宣称它是"当前已完成阶段"。

重裁触发：原型结论为"否定"或"需要先改内核对象模型"时，本裁决与阶段 6 的顺序一起重开。

## D15：SMP 之前的状态分区

**裁决：7-B 的第一步是"状态按 CPU 分区"重构，禁止在单一全局 `BOOTSTRAP_STATE` 上直接
加锁或加 IPI。**

依据：当前是单核全局状态（`kernel/src/bootstrap.rs` 单个 `BOOTSTRAP_STATE`）与按 task
索引的全局调度数组；直接在上层加锁会把顺序瓶颈固定成架构。分区的退出判据沿用计划的
四条：2/4 vCPU 启动、并行 fork/exec 无丢唤醒、TLB shootdown 正确性、扩展性曲线。

重裁触发：若 7-A 的按域状态划分已经覆盖了 7-B 所需的分区，则 7-B 可直接复用并在计划中
改写依赖，不重复一次重构。

## D16：阶段 7 的子轨拆分

**裁决：采纳 7-0 与 7-A…7-H 九条子轨，各自带退出条件；白皮书 §15 阶段 7 按此表述。**

| ID | 子轨 | 优先级 | 退出判据（摘要） |
|---|---|---|---|
| 7-0 | 工程底座 | P0 | `test/lint/tcb/docs check` 在 CI 上绿；5 项基准入库 |
| 7-A | 多 personality 并存 | P0 | 两 personality 各自运行、共享日志、跨域 `EACCES`、单侧崩溃不影响另一侧 |
| 7-B | SMP | P0 | 2/4 vCPU 启动；并行 fork/exec 无丢唤醒；TLB shootdown 正确 |
| 7-C | 资源计量与配额 | P1 | 单 LibOS 耗尽自身配额不影响他人 |
| 7-D | 选择性撤销 | P1 | 服务重启后旧句柄全部 `Stale`，无关域不受影响 |
| 7-E | 动态链接 | P2 | 未修改动态 ELF 白名单运行（D11 的范围） |
| 7-F | IOMMU 与用户态驱动/持久化 | P2 | 从盘启动；文件跨重启持久化；网卡收发 |
| 7-G | 故障恢复与监督 | P2 | 注入崩溃后服务自愈，配额与审计一致 |
| 7-H | 第二架构 | P2（最后） | 同一 POSIR 规范在第二架构通过 `COMPAT-TEST` |

顺序：`7-0 → 7-A → 7-B → 7-C/D → 7-G → 7-E/F → 7-H`。

三条不变的性质（避免把"拆分"读成"承诺"）：

1. 阶段 7 范围仍未冻结；子轨是**排序假设**，不是交付承诺。
2. 每子轨需要自己的退出签署；阶段 7 整体的签署不等于子轨通过，反之亦然。
3. 白皮书原句"范围必须由前面阶段的实证结果决定"继续有效：7-A 原型的结论可以改变
   7-B 之后的顺序与内容。

重裁触发：任一子轨的退出条件被实证推翻，或 7-A 原型给出相反结论时，重开对应子轨。

## 阶段 6 启动条件的直接后果

- **解除的阻塞**：D12 使 S6-X1 的定义可复核；D13 使 S6-M2 的初始栈可完成；S6-M3 的
  profile 行可以按冻结白名单起草。
- **仍在的阻塞**：S6-M1（同步 call/reply 递送）需要架构评审，它不因本裁决而解锁；
  S6-M5 需与 M3/M4 并行启动。
- **仍未做的事**：装载侧的容量缺口（`image_len ≤ 1 MiB`、`MAX_SEGMENT_FRAMES=149`、
  8 页初始栈、流式装载）仍是 S6-M2 的实现工作，见[准备性切片报告](../reports/2026-10-28-stage6-loader-slice.md#未完成清单阶段-6-剩余工作)。
- **阶段 6 是否启动仍由作者决定**：本裁决只说明前置条件可满足，不宣布阶段 6 开始，
  也不改变阶段跟踪中"未开始"的状态与未勾选的交付检查。
