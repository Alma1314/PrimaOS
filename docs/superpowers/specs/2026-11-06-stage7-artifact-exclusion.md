# 阶段7首片：共享镜像工件互斥契约

## 问题与范围

作者于2026-11-06指示“启动阶段7”。本片承接[范围裁决](2026-10-31-stage7-scope-decisions.md)的
7-0工程底座，以[阶段0–6整改](../reports/2026-11-06-stage0-6-review-remediation.md)中的实际失败为输入：
完整BIOS验收与compat并发重建同一个`target/prima-os/prima-os-bios.img`，导致镜像缺失；
另有中止验收后残留QEMU占用镜像的独立失败。

本片解决合作的xtask进程并发构建/使用同一工作区镜像的问题。它不实现子进程监督，
不冻结新的OS机制、应用白名单、SMP/设备平台或性能阈值。现有原语、ABI、镜像、profile、
每轮30秒门限与trace断言均保持。7-0及其它八轨退出条件不因本片勾选。

## 状态与实现前复核

依据是作者启动指令及已确认的7-0范围。本契约在实现前完成本轮技术复核：

- 采用pinned Rust标准库`File::try_lock`，不引入依赖或特权代码；本机工具链源码确认该API可用。
- 锁覆盖共享镜像的完整构建与QEMU生命周期；不能只锁写镜像那一步。
- 竞争必须在任何业务工件变更前返回错误，不能刷新期望输出或重试来隐藏冲突。
- 文件存在不表示被占用；操作系统锁状态才是依据。锁文件在释放后保留，不以删除文件解锁。
- 只修改宿主工具边界，无需修改原语规范、内核对象或冻结profile；不替代独立评审或阶段签署。

[范围裁决的冻结门](2026-10-31-stage7-scope-decisions.md#8-实现前和签署前的冻结门)适用性：
G1–G5/G7涉及的新OS语义、平台、配额、撤销、恢复和证明仍待相应切片定义；
G6五项基准的具体清单与数值门槛继续待确认/实测后冻结；本片只定义G8下的工具验收观察。
这些门没有被本契约整体关闭。

## 成功与失败契约

1. 工作区由xtask编译时`CARGO_MANIFEST_DIR`的父目录确定，与既有镜像路径一致。
2. 资源锁文件固定为`target/prima-os-artifacts.lock`。`target/`按既有忽略规则处理。
3. `build`、`build-linux`、`run`、`test`、全部`test-*`、`compat`、`linux-trace`必须在
   创建业务输出目录、执行参考程序、构建/打包镜像或启动QEMU前取得独占锁。
   `test-musl --host-only`也保守归入该组，避免其宿主检查与共享构建输入交叠。
4. 取得锁后保持文件句柄存活到整个命令返回；成功、错误返回和Rust展开都会关闭句柄并释放锁。
5. 锁已被占用时立即返回非零，诊断包含命令、锁路径与“workspace artifacts busy”；不等待、不重试，
   不启动参考程序/QEMU，不改写已有镜像、fixture或运行日志。仅允许创建/打开宿主锁设施本身。
6. 建目录、打开锁文件或加锁的其它I/O失败均返回确定工具错误；不能绕过锁继续执行。
7. `lint`、`tcb`及不属于上述镜像组的未知命令不为此锁创建任何文件；它们原有的参数检查/行为保持。
8. 不删除活动锁文件，不提供`--force`或跳过开关；删除后创建新inode可能破坏互斥。

锁从xtask进程共同入口开始生效；Cargo/rustup在启动xtask前的编译、下载和缓存管理不在本锁范围，
也不以Cargo自己的缓存锁替代镜像锁。

这是合作进程的宿主工件锁，不是OS资源配额或内核安全原语。默认各工作区使用各自target中的锁；共享同一target目录则共享该锁。
跨工作区的CPU/RAM/端口预算仍由后继CI编排定义。直接运行QEMU、外部写文件以及进程被终止后
仍存活的子进程不受本锁完整监督；不得据此声称故障恢复或任意并发验收已完成。

## 实现与验证

共同入口位于`xtask/src/main.rs`，实现位于`xtask/src/artifact_lock.rs`。
使用标准库非阻塞文件锁；不以PID、超时或锁文件内容判断占用。

| 检查 | 输入与必要观察 |
|---|---|
| 跨进程互斥与释放 | 父进程持锁，独立测试进程取得同一路径失败；父句柄释放后再次成功；锁文件无需删除 |
| 只读路由 | lint/tcb/非镜像未知命令不创建锁设施；镜像命令全部归入互斥范围 |
| I/O失败 | 工作区路径为普通文件等不可创建状态，返回错误而不执行后续步骤 |
| CLI负例 | 外部进程持有真实工作区锁，build/compat/test-process W5立即非零；已有镜像哈希和mtime不变 |
| 正常QEMU | 无竞争时test-process W5与compat沿原验收路径通过；不放宽任何断言 |

执行结果写入[启动报告](../reports/2026-11-06-stage7-start.md)，计划和本契约本身不构成PASS证据。
