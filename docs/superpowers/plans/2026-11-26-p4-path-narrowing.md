# P4 Gate/IPC 路径收窄执行切片

## 目标与基线

把 [LibOS 数据通路契约](../specs/2026-11-10-libos-data-path.md) 的 P4“分段测量、
优化递送/恢复、减少复制”拆成可验收的切片：先固定测量方法与基线，再按同一负载
对比一项收窄，最后做安全/失败原子性回归。P4 不改变抽象所有权与错误语义，不
引入新的 fast path 绕过 Gate 校验，不替代 P5（SMP）与 P6（撤销/恢复）。

- 基线提交：`7590743`（P3-4 收口材料已提交）。
- 本机基线：[P4-0 报告](../reports/2026-11-26-p4-baseline.md)（2026-11-26）。
- 上位：[LibOS 数据通路完整改造计划](2026-11-10-libos-data-path.md)。
- 测量入口：`PRIMA_GATE_CASE=I1|N1|G5 cargo run --locked -p xtask --features gate-probe -- test-gate`。

## 依赖总览

```text
P4-0 ─→ P4-1 ─→ P4-2 ─→ P4-3
```

| 切片 | 依赖 | 类型 | 关闭时提供 |
|---|---|---|---|
| P4-0 方法与基线 | P3 技术交付 | 测量 | 固定负载、阶段定义、两轮原始样本与限制 |
| P4-1 分段确认与候选 | P4-0 | 测量+审查 | 最大耗时段与 1–2 个可证伪的收窄候选 |
| P4-2 单项收窄 | P4-1 | 实现 | 同负载对比、失败原子性保持 |
| P4-3 回归与门限输入 | P4-2 | 验收 | 安全/失败回归、I1/N1/G5/C1、完整套件 |

## P4-0 测量方法与基线

- 交付：报告与本计划；不改代码。
- 方法：
  1. **用户端点总时延**：I1（64 次授权 IPC 往返）、N1（128 次原生 syscall）、
     G5（128 次 Gate 往返），每配置两次独立启动。
  2. **Gate 阶段分解**：G5 的 `trap-queue`、`queue-deliver`、`deliver-reply`、
     `reply-resume`、`kernel-total`、`user-entry`、`user-return`。
  3. **路径计数**：I1 的 direct/queued/blocks；Gate 审计事件。
- 统计：nearest-rank p50/p99；两轮分别记录，不合并宿主/TCG 结果。
- 停止条件：阶段无法区分或采样有观察者效应时停止，登记而不是用总时延替代。

## P4-1 分段确认与候选

- 交付：审查记录与候选清单（可并入 P4-0 报告的后续章节）。
- 工作：把最大段映射到具体代码路径（Gate 绑定/请求表查找、调度 pick-next、
  帧保存/恢复、`SYS_SEND` 直投写回、`gate_copy` scratch 双拷贝），为每个候选
  写出可能收益、风险与可证伪断言。
- 停止条件：候选需要改变抽象语义或放宽校验时停止。

## P4-2 单项收窄

- 交付：一个小范围实现与同负载对比。
- 工作：
  1. 只选一个候选（优先不改变故障原子性的复制/查找消除）。
  2. 保持错误码、审计事件、失败原子性与 Gate 权限校验。
  3. 同负载 I1/N1/G5 两轮对比；不达标就保留现状并记录。
- 停止条件：收窄改变成功/失败语义或审计顺序时停止并登记。

## P4-3 回归与门限输入

- 交付：报告与阶段跟踪更新。
- 验收：`cargo test --workspace`、`cargo xtask lint`、I1/N1/G5/C1、完整 36 组
  72 轮 BIOS；失败保留。
- 不做：性能门槛的最终冻结（需要独立审查与更多宿主样本）。

## 排序与停止规则

1. 先测量后优化；没有同负载两轮样本的收益不作宣称。
2. 安全、失败原子性与审计事件优先于时延。
3. 不引入仅单核有效的共享内存快路径；SMP 留给 P5。
4. 宿主争用、TCG 与 p50/p99 噪声必须随报告保留，不用重跑覆盖。
