# P3-2：前端 v2 接线（Rust 侧交付，C 数据面受阻）

## 结论与范围

本报告记录 P3-2 的实际交付：**Store 直连 v2 会话与 Rust 前端（`Remote`）的 v2
管线、exec 重开与栈预算修复已落盘并通过 72 轮与代理矩阵**。C 适配层的数据面
v2 曾完整实现并在 V1 上跑通，但 W6/W7b 暴露 fork 后父进程 fd 归属反例，已**回退
未交付**；C 进程级文件锁拆分未开始。P3-2 因此**不关闭**，P3 未收口。

## 基线与输入

- 基线：`f621f98`（P3-1 Store v2 会话）。
- 契约：[LibOS 数据通路契约](../specs/2026-11-10-libos-data-path.md) P3 节。
- 计划：[P3 有界异步批量切片计划](../plans/2026-11-18-p3-async-slices.md) 的 P3-2。

## 交付内容（Rust 侧）

### Store 直连 v2

- `service.rs` 为 `MAX_CLIENTS=18` 个直连 Task 槽各加一个 v2 会话；与代理 v2
  分开 VA 区：直连 `ASYNC_DIRECT_BASE=26`，代理 `ASYNC_PROXY_BASE=116`，均按
  5 页/槽。`async_request`/`async_drain` 参数化为 `Store<N>` + 地址函数。
- 直连死亡回收与延迟销毁重试复用 P3-1 的路径；CLOSE 在会话已被回收时幂等。
- 代理 v2 改用独立 tag 族 `0x5f36..0x5f3b`（`+0x0006_0000_0000_0000`），
  直连保持 `0x5f30..0x5f35`；所有 v2 消息的 `slot` 统一在 bits 32..39。
  这样直连 Task 槽与代理索引不会再被同一 tag 路由混淆。

### Rust 前端 v2（`Remote`）

- `connect_v2` 与 v1 `connect` 并存；Linux personality 使用 v2，原生探针保持 v1。
- `open_slot_v2`：`ASYNC_OPEN` → 映射 5 页 → 从控制页读取 generation；
  `exchange_v2`：`Producer::try_publish` → 写数据页（头序号 = ordinal+1）→
  写 tail → doorbell → 等待合并 COMPLETE → 回读状态；`close_slot_v2` 释放映射
  与能力；`reopen` 在 exec 关闭全部 fd 后 CLOSE + OPEN，generation 递增。
- `linux_process.rs::Family::exec` 在 fd 清理后调用 `Session::reopen`；v1/Local
  默认 no-op。会话已死/被回收时的 CLOSE 视为成功，与 v1 代理关闭一致。

### 栈预算（反例驱动）

- 共享 `run` 帧在 P3-2 增至约 7.9 KiB（0x1EE8 + 页保护）。2 页（8 KiB）的
  log/ns 服务在 `run` 序言处把 RSP 压到只读代码页；QEMU `-d int` 记录到
  `IP=0x0b00_0001_da5a, SP=0x0b00_0000_fff8, CR2=0x0b00_0000_fff0`，两个服务
  地址空间重复同一故障，随后整机无进展。
- 修复：普通服务栈 2→4 页（16 KiB），Store 8→16 页（64 KiB）；场景镜像 64 页
  不变。只扩大栈预算，不放宽校验。

## 失败与限制

- **C 数据面 v2 未交付**：临时实现把 read/write 切到 5 页 v2 会话后，V1 全绿，
  但 W6/W7b 失败：`PROC` 的 `cow`/`isolate` 为 0。逐 mode 诊断显示首个子进程
  退出后，父进程 `read(/dev/null)` 返回 `-1/EACCES`（errno 13），其余字段与子
  进程退出码正确；host 参考实现与 C v1 构建均通过。可复现的候选方向是直连 v2
  会话 owner 与 fork 预留/子进程关闭继承 wire fd 的归属交互；**根因未确定**，
  故回退该改动，不把失败路径混入交付树。W7b 同类失败随记录保留。
- **C 进程级文件锁未拆分**：fd/在途引用与延迟 CLOSE 未开始；计划 P3-2 第 3 项
  未完成，P3-2 不能宣称关闭。
- **v2 前端仍是串行交换**：personality 单 Task 每次一页一 doorbell、等待
  COMPLETE；未实现多 gate 在途/park 复用。Store 侧已具备 K=4 与公平轮转。
- 未做 `cat` 的 C v2 机器证据（受阻）；M4-fork 的 v2 证据由代理矩阵覆盖。
- 无 SMP、恢复、性能门槛；不改变 v1 会话、profile v1/v2 与 7-A。

## 阶段/profile 影响

不关闭 P3/P3-2，不改变 P2 状态、阶段 7 九轨勾选或 7-A。契约 P3 节补写了 tag
族、slot 编码与栈预算；P3 仍需 C 数据面与锁拆分、P3-3 矩阵与 P3-4 收口。
