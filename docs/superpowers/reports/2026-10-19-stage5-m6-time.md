# 阶段 5 M6：POSIX 时间首切片（clock_gettime / nanosleep）

**日期**：2026-10-19。**性质**：实测报告。本切片把 `P5-TIME-01` 从 `planned` 推进到
`partial`：`CLOCK_MONOTONIC` 可查询，相对/绝对相对睡眠可用，但**不是**阻塞睡眠、无
`EINTR`、无墙上时钟。本报告不勾选任何 S5-D*/S5-X* 项。

## 1. 范围与设计

| 项 | 实现 |
|---|---|
| 时间源 | 8254 PIT 通道 0，分频 11932（1193182 Hz / 11932 ≈ 99.9985 Hz；名义 10 ms/tick） |
| 计数方式 | **自由运行 + 轮询**：`SYS_TIME_ENABLE=39` 只编程 PIT；`SYS_TIME_TICKS=40` 锁存并读取 16 位倒计数，按模 11932 累计为 64 位 PIT 时钟，再除以分频得到 tick |
| 中断 | **不**配置 PIC、**不**放行 IRQ0、**不**打开用户帧 IF：既有协作阶段执行模型与 `preempt_ready` 见证逐字节不变 |
| `clock_gettime` | 仅 `CLOCK_MONOTONIC`；`tv_sec = ticks/100`、`tv_nsec = (ticks%100)×10 ms` |
| `nanosleep` / `clock_nanosleep` | 时长按 10 ms 向上取整；绝对睡眠仅 `CLOCK_MONOTONIC|TIMER_ABSTIME`；循环轮询 `SYS_TIME_TICKS`，**不** `yield` |
| 错误 | 未知时钟 id/flag、非法 `tv_nsec` → `EINVAL`；`NULL` 指针 → `EFAULT`；非 `NULL` 坏指针由用户态缺页处置（未做内核拷入） |
| 与 Timer 的关系 | `SYS_TIME_TICKS` 直接折算硬件计数，**不**调用 `advance_time`，故不会提前触发阶段 3 的 Timer 见证 |

### 为什么不用中断驱动

先尝试过「tick-only 中断」：由 `SYS_TIME_ENABLE` 启动 PIC/PIT 并把调用者返回帧置
`IF=1`，`preempt_tick` 在非抢占模式下只 EOI/计数。实测在服务阶段第一次 IRQ0 后触发
`#DF`（`timer_entry` 路径从未在协作阶段使用，且它会用进入时内核栈覆盖保存块中的
用户 `RSI`）。该方案被放弃，改为不依赖中断的 PIT 轮询；`preempt_tick` 保持原样。

### 已知边界（写入 profile 的 partial 行）

- 分辨率 10 ms；`CLOCK_REALTIME` 无墙上时钟（`clock_gettime` 返回 `EINVAL`，相对
  `nanosleep` 仍可用）。
- `nanosleep` 是 CPU 轮询，不是阻塞等待；无信号，故不返回 `EINTR`，`rem` 不写回。
- 计数累计要求相邻两次 `SYS_TIME_TICKS` 间隔短于一个 PIT 周期（约 55 ms）；睡眠
  轮询路径满足，但「>55 ms 完全不发该 syscall」会少计。
- 不承诺 `clock_getres`/`clock_settime`/`gettimeofday`/`time`；不进入
  `P5-BOOT-01` 的 auxv/argv 扩展。

## 2. 代码改动

- `prima-abi/src/lib.rs`：追加 `SYS_TIME_ENABLE=39`、`SYS_TIME_TICKS=40`（只追加）。
- `kernel/src/preempt.rs`：`start_time_counter`、`read_pit_count`、`time_ticks`；
  `counter_delta` 的 host 单测覆盖同值、递减与重装回绕。
- `kernel/src/syscall.rs`：两个新号的分派；`time_now_call`/Timer 语义不变。
- `prima-user/c/prima_abi.h`、`prima_syscall.c`：`clock_gettime(228)`、
  `clock_nanosleep(230)`、`nanosleep(35)` 的 Linux 号翻译与时间适配。
- `prima-user/c/stage5_time.c`：同源探针，输出只含通过位，Linux/Prima 可逐字节比较。
- `xtask/src/image.rs`：`Stage5Program::{Probe,Echo,Time}` 三态；时间探针复用
  托管程序通道（单页 argv 块、ECHO tag、排空屏障）与 M5 的文件授权冒烟。
- `xtask/src/qemu.rs`、`main.rs`：`run_bios_test_program`；T1 双轮运行并逐轮比较
  `(queued,direct,blocks)`。

## 3. Linux 参考与 Prima 结果

Linux 参考（`cc -O2 -std=c11 -Wall -Werror prima-user/c/stage5_time.c`，宿主 glibc）：

```
TIME|ok=1;clock=1;nsec=1;mono=1;badclk=1;badptr=1;badnsec=1;zero=1;rel=1;abs=1;past=1
exit=0
```

Prima（QEMU BIOS，`cargo xtask test`，T1 两轮均 PASS）：

```
TIME|ok=1;clock=1;nsec=1;mono=1;badclk=1;badptr=1;badnsec=1;zero=1;rel=1;abs=1;past=1
ECHO|status=0;len=86;hash=2538594173
TASKCAP|id=17;dead=1;root_cleared=1;tasks=12;caps=132
ipc_ready ... queued=45;direct=231;blocks=239
CAPACITY|caps_live=132;caps_peak=141;caps_limit=160;segment_slots=41;segment_limit=48;messages_queued=1;messages_peak=14;messages_limit=32;audit_used=1805;audit_limit=2048
```

- 两轮 `TIME` 行、`ECHO` 长度/FNV-1a、`ipc_ready` 计数逐值一致。
- `audit_used=1805` 高于同 boot 参数下 echo E1 的 785：时间探针的 86 字节 stdout 经
  既有逐字节 `write` + `yield` 通道发送，任务状态迁移随之增长；未超过 2048，且
  `state_audit_ready` 总数/分项一致。该变化是本轮程序的真实计数，不是放宽断言。
- 既有探针与 E1–E6 的期望字节未改；`preempt_ready` 仍为 `ticks=4;pre1=pre2=2`。

## 5. 非承诺

- 不表示 POSIX 时间完整：墙上时钟、`EINTR`、阻塞睡眠、定时器信号、`clock_getres` 均未实现。
- 不把轮询睡眠当作调度器级 `nanosleep`；若后续需要阻塞语义，必须另建可唤醒的等待机制。
- 不改变 `P5-TIME-01` 之外的任何 profile 行，也不勾选 S5-D2–D7/X1–X2。
