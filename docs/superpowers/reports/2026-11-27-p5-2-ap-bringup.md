# P5-2：AP 启动原型（INIT-SIPI-SIPI 到长模式）

## 结论与范围

本切片完成 [S7-B.1 设计](../specs/2026-11-27-stage7-smp-state-partition.md) P5-2 的
**AP 启动原型**：

1. `prima-ostd::smp` 提供位置相关的 AP 跳板模板（16 位实模式 → 32 位保护模式 → 64 位
   长模式），由内核复制到 1 MiB 以下的可执行帧并改写远跳/CR3/栈/入口字段。
2. `kernel::smp` 经 LAPIC INIT-SIPI-SIPI 启动固件报告的每个非 BSP CPU；AP 在长模式下
   执行 `ap_entry`，启用 SSE、置在线位并 `hlt` 停放。
3. 专用 `cargo xtask test-smp-ap` 在 `-smp 2` 与 `-smp 4` 各两轮启动同一镜像，校验
   `aps=1/3;online=2/4`，并复用默认镜像的全部既有启动校验器。

**这不是 SMP 验收**：AP 只在内核态停放，不参与调度；没有每 CPU GDT/TSS/IDT、运行期
CPU 索引、IPI、TLB shootdown、并行 fork/exec 或扩展曲线。7-B 四项退出条件均未勾选，
P5 未签署，P6 未开始。

## 基线与输入

- 代码基线：`bb3e1fa`（P5-1 只读探测已提交）。
- 上位：[S7-B.1 设计](../specs/2026-11-27-stage7-smp-state-partition.md) P5-2；
  [阶段 7 执行计划](../plans/2026-11-06-stage7-execution.md)。
- QEMU：既有 `pc-i440fx-8.2`、TCG 单线程、`qemu64`、128 MiB、`isa-debug-exit`；
  仅把 `-smp 1` 换成 2/4，其余参数冻结。BSP APIC ID 0，xAPIC。

## 实现内容

| 路径 | 内容 |
|---|---|
| `prima-ostd/src/smp.rs` | `global_asm!` 跳板模板（`.prima_ap_tramp` 节）：实模式载 CR3/PAE/GDTR/PE → 32 位置 `EFER.LME|NXE` 与分页 → 64 位桩取栈/索引/入口并跳转；导出模板字节、CR3/索引/栈/入口/GDTR/GDT 偏移与两处远跳字段；常量断言布局 |
| `prima-ostd/src/{arch,mm}.rs` | 新增 `arch::cpuid`（内部保存/恢复 rbx）、`mm::write_u32` |
| `kernel/src/smp.rs` | 帧注册表保留标签 `SMP_FRAME_SEGMENT`；在低内存分配跳板帧；克隆 BSP 高半区 PML4 建 AP 根并把跳板页标识映射；BSP 根上建 LAPIC/跳板可写窗口（PML4 槽 510/509，先验空）；LAPIC SVR/TPR/ICR，INIT→10 ms→SIPI→SIPI，按 TSC 有界等待在线位；`ap_entry` 仅 `enable_sse` + 置位 + `hlt` |
| `kernel/src/main.rs`、`protocol.rs` | 仅 `smp-ap` 下在只读探测后启动 AP，输出 `SMP\|stage=...` 诊断、`SMP\|aps=N;online=M` 与 `SMP\|PASS`；失败输出 `SMP\|FAIL\|...` 并继续正常启动（专用校验器拒绝） |
| `xtask` | 新 feature `smp-ap`、命令 `test-smp-ap`：`-smp 2/4` 各两轮、日志 `target/prima-os/SMPAP-{smp}-{round}.log`、校验 AP/在线数与既有启动校验器 |

实现要点：AP 根只复制 BSP 的 PML4 项 1..511，低半区留空后只标识映射跳板物理页；跳板
帧与 LAPIC 页都不依赖物理直映射（后者实测只读），写入统一走新建的内核窗口。

```text
SMP|rsdp=0;xsdt=0;cpus=4;bsp_apic=0;bsp_index=0;lapic=0xfee00000;lapic_id=0;x2apic=0;online=1
```

`-smp 2` 对应 `aps=1;online=2`。日志 SHA-256：`SMPAP-2-{1,2}` 均为
`0e2f998659ce8f7b20241022e07166cdad19db14f6e8438679338cc752d94916`；`SMPAP-4-{1,2}`
均为 `33d66a499064a80fe5a516fc1998c29d8256e30d5c89c9607dedde5b371a92f2`。剔除
`SMP|` 行后，2 vCPU 与 4 vCPU 的启动输出逐字节相同，且通过同一组既有校验器。

新增 host 用例：跳板布局与符号偏移（`prima-ostd::smp`）、AP 栈顶独立且 16 对齐
（`kernel::smp`）、`validate_smp_ap` 见证正反例（xtask）。

## 失败、反例与限制

首次实现连续三次在 QEMU 失败，均保留排查路径：

1. **LAPIC 写 #PF**：物理直映射中的 LAPIC 页可读不可写（P5-1 只读探测掩盖了这一点）；
   改为在 BSP 根上经 `map_4k` 建可写窗口。窗口槽被占用时确定性失败，不覆盖既有映射。
2. **调试对齐 panic**：模板 GDTR 基址（0x11A）与两处远跳补丁字段不是 4 字节对齐，
   `write_u32` 的 `write_volatile` 对齐前置条件在指令处 panic；改为逐字节写。
3. **AP 三重故障**：AP 的 EFER 只置 LME，未置 NXE；内核页表带 NX 位，AP 首次压栈即
   保留位 #PF，随后 #DF/三重故障。补 `EFER.NXE` 后通过；证据为 QEMU `-d int` 中
   `v=0e e=000a CR2=<栈地址>` 与 `CR4=0x20`/`EFER=0x500`。

限制：

- **AP 只停放**：`hlt` 且 IF=0，不运行任务、不参与调度、不处理中断；没有每 CPU
  GDT/TSS/IDT，也不加载 BSP 的 IDT（AP 故障会三重故障）。
- **无 IPI/TLB shootdown**：AP 的 LAPIC 未使能 SVR，BSP 不发除 INIT/SIPI 外的 IPI。
- **xAPIC only**：MADT 报 x2APIC 时直接拒绝；未实现 x2APIC MSR 发送/中断重映射。
- **MMIO 窗口为 WB 映射**：QEMU 通过；未设置 PCD/PWT，不宣称真机缓存语义。
- **低页与窗口约束**：跳板帧须在 `0x1000..0x9F000`；PML4 槽 510/509 必须为空，否则
  确定性失败。跳板页经帧注册表保留标签归属，不暴露 Capability。
- **失败策略**：AP 超时只输出 `SMP|FAIL|...` 并继续正常启动，由专用校验器判失败；
  没有运行时 panic，也没有按失败 CPU 精确报告（AS 字符串只有类别）。
- 未处理 AP BIST、已在线 AP 的重启、SIPI 向量冲突或 4 个以上 CPU；扩展曲线与并行
  fork/exec 未测。

## 阶段/profile 影响

不勾选 7-B 或任何阶段 7 退出条件；不改变 profile、默认 boot 事件、默认 QEMU `-smp 1`
或默认镜像（`smp-ap` feature 之外不编译 AP 启动）。阶段 7 的 P5 推进到
“P5-2 AP 启动原型”，P5 未签署，P6 未开始。
