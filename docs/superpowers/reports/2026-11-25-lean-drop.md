# Lean `Formal.Drop`：`cap_drop` 规范层最小模型（§4.5）

## 结论与范围

本报告记录 COSIR §4.5 `cap_drop` 的 Lean 参考语义：新增
`lean/Formal/Drop.lean` 与 `lean/Checks/Drop.lean`。复用
`Formal.TokenLocation` 的 `Snapshot`/`dropToken`，只补规范层性质（单位置删除、
不传播、记录保留、structural 守卫）。10 条定理通过 `lake build`，公理仅
`propext`/`Quot.sound`，并有可执行 `#eval` 锚。

本切片是主机可执行模型证据，不是内核 Rust 细化、订阅终止或审计事件证明。

## 基线与输入

- 基线：`5583cfc`（另加 `fd844ac`、`01dc0fe`、`5cc574b`、`d212cb1`）。
- 契约：COSIR §4.5（`cap_drop`）、§4.6（位置删除）。
- 复用：`Formal.TokenLocation` 的原子位置更新与 `Consistent`。
- 映照契约：[lean/README.md](../../../lean/README.md) 的 2026-11-25 Drop 节。

## 实现

- `drop s caller c := dropToken s caller c`：要求 `locations c = HeldBy caller`
  且 `structural c = false`。
- `drop_clears`：成功后目标位置为 `none`。
- `drop_keeps_other`：其他位置不变。
- `drop_does_not_propagate` / `drop_parent_child_independent`：派生子项的位置与
  记录保留——规范“丢弃父 Capability 不撤销已派生子项”。
- `drop_keeps_caps` / `drop_preserves_wellformed`：caps 与 CDT parent 结构不变。
- `drop_structural_fails` / `drop_wrong_holder_fails`：守卫失败返回 `none`。
- `drop_consistency`：`Consistent` 保持；`drop_idempotent`：二次 drop 失败。

`#eval` 锚：派生 child drop 成功、structural 根与错误持有者拒绝、目标位置清空、
父记录保留（`some (heldBy 9)`）、子记录保留。

## 失败与限制

- 不覆盖：订阅终止（§12.4 的“最后一个 `ExcSubscribe` 丢失时终止订阅”）、审计
  事件、跨位置移动竞争、真实 Rust `cap_drop` 路径或 W3 唯一位置。
- 未与 `Formal.Revoke` 共用实现：Revoke 是子树失效，Drop 是单位置
  （可执行）；规范明确二者正交，本模型不把撤销隐含进 drop。
- 本次未改 Rust，未重跑 workspace/QEMU/lint。

“未覆盖”移入“最小可执行模型”，订阅/审计边界保留。
