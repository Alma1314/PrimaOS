# Lean `Formal.Move`：§4.6 位置迁移与 W3 唯一位置最小模型

## 结论与范围

本报告记录 COSIR §4.6（Capability 移动）与 W3（单一位置）的 Lean 参考语义：新增
`lean/Formal/Move.lean` 与 `lean/Checks/Move.lean`。复用
`Formal.TokenLocation` 的 `Snapshot`/`Consistent`/`replace`，把规范列出的位置变化
抽成 `Transition {src, dst, msgId}` 转移表与单位置原子 `applyMove`。15 条定理通过
`lake build`，7 条无公理、其余仅 `propext`，并有可执行 `#eval` 锚。

本切片是主机可执行模型证据，不是 W4 容器双向一致、并发移动、审计事件或 Rust
细化证明。

## 基线与输入

- 基线：`5583cfc`（另加 `fd844ac`、`01dc0fe`、`5cc574b`、`d212cb1`、`1fed6da`、
  `05c80a5`）。
- 契约：COSIR §4.6（移动）、W3（单一位置）、§8.5（跨节点 `NonPortableCap`）。
- 复用：`Formal.TokenLocation` 的原子位置更新、`Consistent` 与 carrier 视图。
- 映照契约：[lean/README.md](../../../lean/README.md) 的 2026-11-25 Move 节。

## 实现

- `Transition {src, dst, msgId}`：一次位置变化的原位置、新位置（删除为 `none`）与
  直投 `MsgId`。
- 转移表：`queuedSend`（`HeldBy sender → InMessage msg`）、`directSend`
  （`HeldBy sender → HeldBy receiver`，记 `msgId`）、`recvDeliver`
  （`InMessage msg → HeldBy receiver`，记 `msgId`）、`taskCreate`、`nsBind`、
  `nsUnbind`、`deletion`（任意源 → `none`）。
- `applyMove s c t`：仅当 `locations c = some t.src` 时成功，返回一次 `replace` 后的
  `Snapshot` 与记录的 `Transition`；否则 `none`（外层操作失败即不移动）。
- `crossNodeSend s transferred`：v1 跨节点 `send` 不产生位置变化；非空
  `transferred` 返回失败（对应 `NonPortableCap`），且状态不变。
- `Formal.Location` 不含 `InTransit`，模型由构造排除该位置（W3 v1）。

已证性质（15 条）：

- 操作：`applyMove_requires_source`、`applyMove_dest`、`applyMove_event`、
  `applyMove_keeps_caps`。
- 一致性：`applyMove_preserves_consistency`、`carriers_after_move`。
- 唯一性：`w3_unique_location`。
- 转移表：`queuedSend_dest`、`directSend_msgId`、`recvDeliver_msgId`、
  `nsBind_dest`、`deletion_sink`。
- 跨节点：`crossNodeSend_no_move`、`crossNodeSend_empty_ok`、
  `crossNodeSend_nonportable_fails`。

## 失败与限制

- **抽象边界**：位置转移表只覆盖单 token 的原子一步；`queuedSend`/`recvDeliver`
  的消息存在性、`taskCreate` 的任务发布、`nsBind`/`nsUnbind` 的路径解析与外层授权
  检查均作为调用方前置，未建模。
- **W4 未覆盖**：`HeldBy(t)` 要求 Task 活动、`InMessage(m)` 与消息 `caps` 双向一致、
  `InNamespace(n,p)` 与 Namespace `entries[p]` 双向一致、消息列表无重复、路径至多
  一个 Capability——这些容器一致性不在本模型。
- **原子性表述**：`applyMove` 是单步状态函数，成功结果直接携带新位置；没有时序或
  并发模型中“中间不可观察”的形式化。并发移动竞争、跨节点版本与订阅终止不覆盖。
- **审计事件**：模型记录 `Transition` 结构，但未建模 §13.1 的 `CapMoved`/
  `CapDropped` 信封、`EventId`、`now` 或事件序列。
- 不构成 W3 的内核实现证明或 Rust 源码细化；cosir `TokenLocation` 的 host 测试是
  独立实现证据。

## 阶段/契约影响

“最小可执行模型”，W4 容器与审计边界保留。
