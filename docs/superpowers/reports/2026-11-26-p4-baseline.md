# P4-0：Gate/IPC 分段测量基线与候选

## 结论与范围

本报告固定 P4 的测量方法与本机基线：I1（64 次授权 IPC 往返）、N1（128 次原生
syscall）、G5（128 次 Gate 往返，含 5 个用户/Kernel 阶段），各自两次独立启动。
**本片不改任何代码**，只记录原始端点结果、阶段占比与静态候选；数值限本机单核
TCG 与当前宿主争用，不构成跨主机门槛，也不与 2026-11-07 的远端样本合并。

## 基线与输入

- 基线提交：`7590743`（P3-4 收口材料已提交）。
- 计划：[P4 Gate/IPC 路径收窄执行切片](../plans/2026-11-26-p4-path-narrowing.md)。
- 上位：[LibOS 数据通路契约](../specs/2026-11-10-libos-data-path.md) P4；
  [完整改造计划](../plans/2026-11-10-libos-data-path.md)。
- 命令（每个配置两轮）：
  `PRIMA_GATE_CASE=<I1|N1|G5> CARGO_NET_OFFLINE=true cargo run -q --locked -p xtask --features gate-probe -- test-gate`
- 原始串口：`target/prima-os/S6GATE-1.log`、`S6GATE-2.log`（ignored）。

## 测量方法

| 层 | 入口 | 观察 |
|---|---|---|
| 用户端点 | I1/N1/G5 `user-total_ns` | 一次请求/答复的 wall 时间（RDTSC，user wrapper 边界） |
| Gate 阶段 | G5 `trap-queue`/`queue-deliver`/`deliver-reply`/`reply-resume` | 内核递送与恢复的分段 |
| 边界 | G5 `user-entry`/`user-return`/`kernel-total` | 用户/内核切换与合计 |
| 路径计数 | I1 direct/queued/blocks；Gate 审计 | 递送是否直投、排队或阻塞 |

统计为 nearest-rank p50/p99；两轮分别保留。

## 本机基线（2026-11-26）

### I1（64 samples，授权 IPC 往返）

| 轮 | hz | user-total p50（ns） | p99（ns） |
|---|---|---|---|
| 1 | 2,088,439,494 | 1,577,222 | 8,785,152 |
| 2 | 2,086,791,719 | 2,491,118 | 12,905,501 |

### N1（128 samples，原生 syscall）

| 轮 | hz | user-total p50（ns） | p99（ns） |
|---|---|---|---|
| 1 | 2,083,175,873 | 47,006 | 93,700 |
| 2 | 2,085,111,044 | 47,124 | 140,093 |

### G5（128 samples，Gate 往返）

| 阶段 | 轮 1 p50 / p99（ns） | 轮 2 p50 / p99（ns） |
|---|---|---|
| trap-queue | 206,862 / 377,708 | 202,069 / 331,996 |
| queue-deliver | 1,401,843 / 3,587,202 | 1,412,948 / 2,232,863 |
| deliver-reply | 834,130 / 1,371,001 | 821,682 / 1,366,376 |
| reply-resume | 442,842 / 693,743 | 436,941 / 595,660 |
| kernel-total | 2,890,371 / 5,152,183 | 2,887,957 / 4,012,582 |
| user-entry | 105,762 / 216,608 | 106,277 / 208,918 |
| user-return | 10,542 / 26,261 | 10,395 / 25,246 |
| user-total | 3,007,715 / 5,266,531 | 3,005,539 / 4,151,288 |
| hz | 2,081,493,799 | 2,078,703,641 |

**观察**：本机 G5 的 `queue-deliver` 占 kernel-total 的约 48%（p50），
`deliver-reply` 约 29%；`trap-queue` 与 `reply-resume` 合计约 23%。用户 entry/return
相对小。I1 的 p50 约 1.6–2.5 ms，N1 约 47 µs；I1 的 p99 波动明显大于 N1。

## 静态候选（待 P4-1 确认）

| 候选 | 位置 | 可能收益 | 风险/断言 |
|---|---|---|---|
| Gate 请求从队列到服务交付的查找与唤醒 | `kernel/src/gate.rs`（`gate_trap`/`gate_wait`/绑定表） | 最大段；减少重复绑定/持有者查找 | 不得跳过权限或审计；请求顺序与失败原子性保持 |
| 帧保存/恢复与调度选择 | `kernel/src/sched.rs`、`resume`/`pick_next` | `deliver-reply`/`reply-resume`；减少无效扫描 | 不改变阻塞/直投语义 |
| `gate_copy` 的 4KB scratch 双拷贝 | `kernel/src/syscall.rs:4322` | 一次 copy 改为直接同页写（或减少 scratch） | 保持双端页权限校验与 COW；错误码不变 |
| `SYS_SEND` 直投写回 24 B + caps | `kernel/src/syscall.rs:3173` | 小；合并写回 | 保持消息/能力位置与审计顺序 |
| Gate 请求元数据 96 B 输出 | `prima-runtime/src/gate.rs:155` | 小 | ABI 布局冻结 |

## 失败与限制

- **宿主争用**：测量期间同机存在其他构建活动；I1 的 p99（8.7–12.9 ms）明显高于
  p50，不能解释为稳定尾延迟。原始两轮样本分别保留。
- **TCG/单核**：QEMU TCG 与单核调度不代表硬件或 SMP；P5 前不设性能门槛。
- **跨主机不可比**：本机 N1 p50 约 47 µs，与 2026-11-07 远端 CI 的约 24.7 µs
  不同源，不合并、不据此推断回归。
- **阶段边界**：`user-entry`/`user-return` 由 user-wrapper 边界定义；内核内部
  更细的采样不在本片范围，若 P4-1 需要需新增可选探针并登记观察者效应。
- 本报告未改代码、未做优化、未设门限。
